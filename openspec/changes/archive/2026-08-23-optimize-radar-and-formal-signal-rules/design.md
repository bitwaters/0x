## Context

当前服务是一个 Node.js/TypeScript 长驻进程，使用 SQLite WAL，模块分为 discovery、qualification、telegram 与 evaluation。GMGN Top100 同时承担内部发现和雷达激活，导致任意名次的一次双榜或三次上升都可能公开；资格中的部分瞬时失败会进入终态，发送前 CoinGecko 请求只有单请求超时而没有整体 5 秒预算；发布状态仍依赖前 20 个连续验证序号，`ENTRY_UNAVAILABLE` 会阻塞晋级。详见 proposal.md 与本变更四份规格。

既有完成变更已经归档并同步到 `openspec/specs`。本提案只维护 `trending-candidate-discovery`、`fixed-pool-signal-qualification`、`telegram-signal-delivery` 与 `signal-evaluation` 四份 delta；实施修改现有模块，不复制第二套运行管线。

## Goals / Non-Goals

**Goals:**

- 内部覆盖 Top100，公开雷达只展示持续确认的低市值强热度候选。
- 用一个清晰状态机同时支持 Bonding、新池、老池复苏与单卡编辑。
- 在现有 GMGN/CoinGecko 请求上计算成交金额质量，不增加外部 API 或额外轮询周期。
- 将暂时波动变成有界等待，将硬风险继续保持终态。
- 用每链 5 条可评估样本快速开放 Beta，并按规则版本持续积累证据。

**Non-Goals:**

- 不承诺盈利、胜率或可执行净收益，不自动交易或替用户下单。
- 不增加评分模型、机器学习、VWAP、多周期技术指标、多档公开信号或全局每小时硬限额。
- 不更换 GMGN 最大池，不用 CoinGecko 重新发现候选，也不引入第三方市场/安全 API。
- 不在本变更中修改最终 Telegram 卡片视觉设计。

## Decisions

### 1. 一条内部候选管线，公开雷达作为可选投影

候选创建范围改为 `$10K–$300K`，所有候选继续进入池解析；公开 Bonding 雷达使用独立的 `$10K–$100K`、Top5 和持续确认门槛。真实池公开状态使用 `$20K–$300K` 与 Top20。这样公开降噪不会切断正式信号来源。

替代方案是直接把 GMGN 请求缩到 Top5；该方案会丢失尚未进入 Top5 但随后快速开池的候选，因此不采用。

### 2. 雷达 outbox 保持唯一，但增加可恢复编辑

继续使用每链、Token、`radar` 消息唯一性，在首次发送后复用现有 outbox 的 message id 与 payload 保存最新期望内容，并仅为 outbox 增加一个已应用 payload 哈希。期望 payload 哈希与已应用哈希不同时表示待编辑；编辑成功后更新已应用哈希，进程重启可据此恢复。Bonding 到真实池以及终态均更新同一消息，不新增第二套雷达状态表，也不补发重复卡。

### 3. 新池和复苏共用资格器，只改变激活条件与基线

候选记录新增 `opportunity_type`、`activation_at_ms`、`activation_price_usd` 与 `activation_rule_version`。新池按池龄 `≤30m` 激活；复苏按持续双榜或三次上升至 Top20 激活。两条通道进入同一 GMGN 安全、CoinGecko 固定池和成交规则，避免复制逻辑。固定池资格记录再保存本次窗口第一次完整通过时的 `qualification_reference_price` 与时间，后续重试只读且不得覆盖。

80%决策 high-water 从不可变activation price计算；现有首次发现价与发现后high-water继续只用于雷达/卡片展示和审计，两个口径使用不同字段，不互相覆盖。

### 4. 规则变更只有限重开旧终态

部署迁移可一次性重开从未发送且仅因 `POOL_TOO_OLD`、`POOL_AGE_OUT_OF_RANGE` 或旧首次发现基线 `CHASE_LIMIT_EXCEEDED` 终止的候选，使其在再次满足新激活条件时建立新基线。安全失败、池组成冲突、池消失、已发送和其他终态不得重开。迁移记录原终态、迁移规则版本与时间，保证可追溯。

替代方案是所有旧终态永不重开；该方案会让已被旧池龄规则见过的代币永远无法进入复苏通道，因此不采用。

### 5. 暂时失败采用 WAIT 和滑动首样本，但窗口不重置

固定池绑定时间继续定义唯一 120 秒截止时间。流动性大于零但低于门槛、下降超过10%、成交额/比例不足、排名衰退和发送前漂移越界都返回 WAIT。流动性样本失败时以当前合法同池详情替换内存首样本，再等待10秒；不得修改资格开始时间。

池消失、归零、组成变化、安全硬失败和激活后 high-water 超过80%仍为终态。这在容忍 Meme 波动的同时阻止无限重试。

### 6. 成交质量使用同一批规范化 trades

现有最近30秒、最多10笔去重成交继续作为唯一输入，在一次遍历中同时计算 `totalUsd`、`buyCountRatio`、`buyUsdRatio` 和 `largestTradeRatio`。`buyUsdRatio≥0.60` 取代 `netBuyUsd>0` 的布尔门槛；`netBuyUsd` 仍作为展示和审计事实保留。最低 `$500` 作为 `$100` 参考人工买入的初始活跃度门槛。

不增加额外 CoinGecko 请求，也不计算综合分数，便于将后续表现变化归因到具体阈值。

### 7. 发送前复核使用整体截止时间

Telegram 发送服务为两次 CoinGecko REST 调用共享一个 5 秒 AbortSignal/deadline，而不是让每个请求各自最多重试三次。复核不建立第二组10秒稳定样本；它检查同池组成、绝对流动性、深度、对手侧下降20%、完整成交质量、最新成交5秒和相对不可刷新资格参考价的 `-5%～+8%` 漂移。

复核暂时失败不改变候选终态，运行循环最早3秒后再次资格和发送检查；`isCandidateSendable` 同时验证原120秒截止与规则版本，防止慢请求完成后发送过期快照。

### 8. 直接统计可评估成熟样本

保留所有 delivered samples 与现有发送序号，不增加第二套序号。模拟入场改为 Telegram 回执后10秒内第一笔同池有效成交；Beta 查询直接统计当前链、epoch、validation stage 中具有有效入场且15分钟状态为 `COMPLETE`、`AMBIGUOUS` 或 `TERMINAL_NEGATIVE` 的样本，`ENTRY_UNAVAILABLE` 和 `PROVIDER_MISSING` 自然不进入计数。

达到5条可评估成熟样本只触发技术 Beta；报告明确不作盈利声明。复盘里程碑按chain与decision rule version计数，在同一报告内再按opportunity type与delivery stage分层，避免为每个分组维护独立里程碑。

## Risks / Trade-offs

- [Top5 持续确认会减少公开雷达并可能晚几秒] → 内部 Top100 不受影响，正式资格不依赖公开卡。
- [`$500` 与 60% 买入金额可能对两链影响不同] → 按链和机会类型分段报告，累计20条后一次只调整一个阈值。
- [五条样本统计意义很弱] → 只作为技术发布门槛，卡片和报告不得宣称盈利验证完成。
- [流动性重采样可能让震荡池反复等待] → 原120秒截止不可延长，归零、池消失和组成变化立即终止。
- [5秒整体预算在供应商抖动时减少发送] → 超时只暂停本轮并重试，禁止使用旧数据放宽门槛。
- [编辑旧雷达卡可能被 Telegram 限流或消息不可编辑] → 持久化期望状态并退避重试，保持一币一卡且记录可见失败。
- [一次性重开旧终态可能产生候选突发] → 只重开三个明确旧规则原因且仍未发送的记录，后续必须重新满足新激活和全部新资格。

## Migration Plan

1. 只添加机会类型、激活决策high-water、资格参考价和outbox已应用payload哈希所需的向后兼容SQLite字段/索引与新规则版本；先运行迁移与现有数据备份验证。
2. 实施内部/公开雷达分层与雷达卡编辑，在 Telegram 关闭或私有频道中验证状态迁移。
3. 实施机会类型、激活基线、有限旧终态重开及 WAIT 重采样；使用保存的原始响应回放边界场景。
4. 实施成交金额质量和5秒整体发送前复核，再启用新的资格规则版本。
5. 实施10秒入场、直接可评估计数和每链5条 Beta 门槛；确认旧样本仍按旧规则版本查询。
6. 本地测试和 dry-run 通过后，按既有“本地修改、推送、服务器拉取部署、只读日志检查”流程发布，服务器不得直接修改文件。
7. 回滚时部署上一镜像/提交并恢复上一规则版本；新增字段保持向后兼容，不删除新审计记录。若新规则导致关键错误，链进入 `SUSPENDED`，修复后开启新 validation epoch。
