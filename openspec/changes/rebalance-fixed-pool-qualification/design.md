## Context

资格器已具备固定池、成交、流动性和发送前复核能力；本次只调整参数与单进程调度。生产配置仍显式包含旧120秒值，因此规则版本应由代码中的统一资格策略决定，避免部署时修改服务器密钥文件。

## Goals / Non-Goals

**Goals:**
- 恢复少量非零的低市值固定池信号，同时保持安全与真实池边界。
- 降低旧PREHEAT对GMGN预算和短资格窗口的竞争。
- 用低成本日志识别后续真实WAIT分布。

**Non-Goals:**
- 不放宽GMGN安全、流动性、追高或发送前漂移规则。
- 不新增API、数据库表、并行工作队列或后台服务。

## Decisions

1. 成交门槛继续集中在现有纯规则函数中，删除买入笔数硬判断但保留该统计作为证据，避免第二套评分机制。
2. 资格窗口固定为策略常量180秒并进入规则版本；保留环境变量解析仅用于兼容配置检查，但运行规则使用统一策略值，防止服务器旧私密配置覆盖新规范。
3. 调度只增加状态优先级和现有持久化1m快照预筛，不并行扩容资格请求。
4. WAIT诊断使用内存计数器按分钟随现有进度日志刷新，不持久化逐次事件。
5. 雷达首次发送价与涨幅随现有outbox payload保存；后续编辑从该不可变基线更新推送后最高，不迁移旧消息。

## Risks / Trade-offs

- [60秒窗口仍可能错过极低频BSC池] → 180秒内重复评估，先用WAIT分布验证，不继续放宽。
- [旧雷达没有推送价字段] → 保持旧“发现后最高”兼容展示，新消息使用新口径。
- [进程重启会清空WAIT聚合] → 诊断只面向运行趋势，不作为审计事实。

## Migration Plan

1. 本地执行全量检查并生成新规则版本。
2. 推送后服务器仅执行Git拉取和Docker Compose重建。
3. 检查启动配置、WAIT聚合、资格漏斗和容器健康；异常时回滚Git提交并重建，不修改服务器文件。
